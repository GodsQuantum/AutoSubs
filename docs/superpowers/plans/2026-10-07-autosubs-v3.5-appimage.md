# AutoSubs v3.5 Native Linux AppImage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a tested, reproducible x86_64/aarch64 AppImage distribution that runs the existing AutoSubs backend/UI and workflow supervisor with safe per-user defaults.

**Architecture:** Keep application behavior in existing Rust/Svelte code. Add AppImage-native packaging only: POSIX `AppRun`, desktop/AppStream metadata, reproducible AppDir/AppImage builder, and release workflow jobs. Bundle a baseline FFmpeg/fontconfig/curl toolchain with linuxdeploy while leaving GPU drivers host-provided.

**Tech Stack:** Rust 1.98.1, Svelte/Vite, POSIX shell, linuxdeploy, appimagetool, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-07-autosubs-v3.5-appimage-design.md`

## Global Constraints

- Docker behavior and Cloud9 production mounts must not change.
- AppImage mutable state lives under XDG user directories.
- Default bind address is `127.0.0.1`; default port is `3051`.
- Allowed roots must never default to `/`.
- Existing Rust workflow supervisor remains the only watcher.
- linuxdeploy/appimagetool downloads are SHA-256 pinned.
- Release architectures are x86_64 and aarch64.
- GPU drivers remain host-provided.
- Package includes a bundled FFmpeg/libass software baseline.
- Feature release version is `3.5.0`.

## Review Focus

- Paths with spaces/non-ASCII remain correctly quoted.
- Second launch reuses an existing healthy instance.
- No system FFmpeg/fontconfig still yields bundled baseline.
- Newer system tools are opt-in without editing the AppImage.
- Graphical launch preserves logs under XDG state.
