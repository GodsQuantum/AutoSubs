# AutoSubs v3.5 Native Linux AppImage Design

**Date:** 2026-10-07
**Status:** approved for inline execution by the user's instruction to continue and finish the remaining AutoSubs work
**Base:** AutoSubs v3.4.0 (`a56db81`)

## Goal

Ship AutoSubs as a real native Linux AppImage in addition to Docker, without a second backend or watcher implementation. The AppImage runs the same Rust server, Svelte UI, renderer, transcription integrations and `workflows::run_supervisor`.

## User experience

A user downloads `AutoSubs-<version>-<arch>.AppImage`, makes it executable and runs it. Normal launch initializes per-user state, binds to loopback, starts AutoSubs, opens the local UI after `/api/v1/health` is ready, and keeps the backend/workflows alive after the browser closes.

`--background` and `--no-browser` suppress browser opening so the same AppImage can be used from XDG autostart or another user-session launcher.

## Distribution contract

Release assets:
- `AutoSubs-<version>-x86_64.AppImage`
- `AutoSubs-<version>-aarch64.AppImage`
- one SHA-256 checksum file per artifact.

Docker remains unchanged.

The package is a Type 2 AppImage/AppDir with root `AppRun`, one desktop entry, icon/`.DirIcon`, `usr/bin`, `usr/share/applications`, `usr/share/icons`, and `usr/share/metainfo`. AppStream metadata is validated.

## Runtime paths

Mutable state never lives in the read-only AppImage.

- config: `${XDG_CONFIG_HOME:-$HOME/.config}/autosubs`
- data: `${XDG_DATA_HOME:-$HOME/.local/share}/autosubs`
- fonts: `${XDG_DATA_HOME:-$HOME/.local/share}/autosubs/fonts`
- state/logs: `${XDG_STATE_HOME:-$HOME/.local/state}/autosubs`
- frontend: `$APPDIR/usr/share/autosubs/frontend`
- host: `127.0.0.1`
- port: `3051`

Existing `AUTOSUBS_*` variables override these defaults.

Default allowed roots are limited to the AutoSubs data directory, `$HOME`, and existing `/mnt`, `/media`, `/run/media/$USER`. The launcher never defaults to `/`.

## Media/runtime dependencies

The AppImage bundles a deterministic fallback toolchain collected by linuxdeploy from the build runner: `ffmpeg`, `ffprobe`, `fc-list`, `fc-scan`, `curl`, and their non-excluded user-space libraries. glibc, kernel interfaces and GPU drivers/ICDs remain host-provided.

Bundled tools are preferred by default. `AUTOSUBS_USE_SYSTEM_MEDIA_TOOLS=1` puts host tools first for rolling distributions with newer FFmpeg/GPU support.

No transcription model is bundled; existing OpenAI-compatible local/remote transcription and alignment settings are reused.

## Folder workflows

There is no AppImage watcher. Existing `workflows::run_supervisor` remains authoritative, using `notify` plus reconciliation scanning. Closing the browser does not stop workflows; stopping the AppImage process does.

## Launcher contract

`AppRun` is the only packaging wrapper required by AppImage. It must:
- create safe XDG config/data/fonts/state directories;
- preserve explicit `AUTOSUBS_*` settings;
- bind to loopback by default;
- construct safe allowed roots;
- prefer bundled media/font tools unless explicitly overridden;
- reuse an already-running healthy AutoSubs instance instead of launching a duplicate;
- wait for health before opening the browser;
- try `xdg-open`, then `gio open`, otherwise print the URL;
- preserve backend arguments except launcher-only `--background` and `--no-browser`;
- log to the terminal when attached, otherwise append to XDG state.

## Packaging and supply chain

Packaging lives under `packaging/appimage/`. Official `linuxdeploy` and `appimagetool` continuous artifacts are SHA-256 pinned. A changed upstream asset fails closed until intentionally updated. CI uses extract-and-run mode so FUSE is not required.

## CI and release

The release workflow builds x86_64 and aarch64 AppImages on native GitHub runners, runs version and real health/libass smokes, creates checksums, and uploads all artifacts to the same GitHub Release as the container image.

## Security

- loopback-only by default;
- no `/` allowed-root default;
- SQLite stays in local XDG config;
- no root installation;
- no embedded credentials;
- digest-verified packaging tools;
- Docker and Cloud9 mounts remain untouched.

## Non-goals

No Electron/Tauri shell, second watcher daemon, root installer, automatic system service creation, bundled GPU driver, bundled ASR/LLM model, or Docker replacement.
